Урок 0002 · Основы · ~20 минут

Свойства

Свойства — это данные о заметке: год, статус, где лежит, кто использует. Научишься узнавать тип свойства, писать его без ошибок и говорить Claude, какие свойства ставить.

Цель урока. Посмотреть на любую строку свойств и сказать: какой это тип и записано ли оно правильно. Например: used_by в Kolnatun — List, line — Number.

1. Свойство = имя + тип + значение

Из урока 0001: свойства стоят в начале файла между двумя ---, каждая строка — имя: значение. Этот блок называют frontmatter, а формат записи — YAML (простой текстовый формат «ключ: значение»).[свойства]

Имя — любое, но в одной заметке каждое имя только один раз.[свойства] У каждого свойства есть ещё тип — какие значения в нём бывают. Тип виден иконкой слева от имени в таблице свойств.

Главное правило. Тип принадлежит имени, а не заметке. Если year — Number, то year — Number во всех заметках хранилища.[свойства] Поэтому одно имя — всегда одинаковые по смыслу значения.

Внимание: where: HDD-2TB-01 — это Text, хотя там цифры. Number — только когда всё значение число. А дата на экране показывается в формате твоей Windows, но в файле всегда 2026-10-06.[свойства]

3. Три встроенных свойства

Эти имена Obsidian знает сам; все три — списки.[свойства]

#СвойствоЧто делает
1tagsтеги заметки — короткие метки для поиска и группировки. Синтаксис — ниже, в 3.1.
2aliasesдругие имена заметки. Начинаешь писать ссылку [[Tarkovsky — в подсказках появится псевдоним со значком изогнутой стрелки; Enter создаст [[Тарковский|Tarkovsky]].[псевдонимы]
3cssclassesоформление заметки через CSS. Нам не нужно.

Старые имена tag, alias, cssclass устарели с версии 1.9 — пиши tags, aliases, cssclasses.[свойства]

3.1. Синтаксис тегов

Тег — метка вида #фантастика. По тегу потом ищут (tag:фантастика, урок 0004) и смотрят все теги хранилища списком (Tags view).[теги] Поставить тег можно двумя способами — результат одинаковый:

#ГдеКак пишется#
1в тексте заметкиПересмотреть зимой #пересмотретьнужен: # и сразу слово
2в свойстве tagstags:
  - пересмотреть		не пишется

В вики, которые пишет Claude, теги ставим только в свойстве tags: их видно сразу, в одном месте.

Из чего состоит тег (строка - кино/советское: «- » — разметка списка, тег — кино/советское):[теги]

#ПравилоМожноНельзя
1буквы (любой язык), цифры, _, -, /, эмодзифантастика, sci-fi, кино/советское—
2без пробела внутри — слова склеивают через _ или -научная_фантастиканаучная фантастика
3хотя бы одна не-цифраy19841984
4регистр не важен: Кино и кино — один тегв списке тегов показан так, как написан впервые

Что делает / — вложенный тег. / делит тег на уровни: кино/советское = тег советское внутри тега кино. Как папки, только для меток.[теги]

Пример: три заметки, у каждой одна строка в tags.

#ЗаметкаСвойство
1Сталкер (1979)tags:
  - кино/советское
2Солярис (1972)tags:
  - кино/советское
3Матрица (1999)tags:
  - кино/зарубежное
#ГдеЧто получится
1поиск tag:киновсе три: родитель находит кино и всё, что под ним[теги]
2поиск tag:кино/советскоетолько Сталкер и Солярис
3Tags viewдеревом: кино → советское, зарубежное[теги]

Для Kolnatun то же самое: calc/AcademicEnd, calc/SalaryCalc → tag:calc найдёт оба калькулятора.

#Не поддерживаетсяПример, который не сработает

  name: Тарковский
2Markdown внутри значения — **жирный** останется звёздочкамиcomment: **шедевр**

Это сделано специально: одно свойство — один простой факт.[свойства] Нужна структура — заведи несколько свойств (director, director_born) или отдельную заметку (Люди/Тарковский).

7. Проверь себя

8. Теперь в настоящем Obsidian

Открой учебное хранилище practice-vault (как в уроке 0001). В нём появились две новые заметки: Медиатека/Фильмы/Солярис (1972) и Люди/Тарковский.

  1. Типы. Открой Солярис (1972). Иконка слева от имени свойства показывает его тип. Сверь каждую с таблицей внизу заметки. Если тип другой (например, added не Date) — нажми на иконку и выбери нужный тип из списка.[свойства]
  2. Новое свойство. Поставь курсор в текст заметки, нажми Ctrl+;. Имя rating, значение 8. Потом нажми иконку слева от rating и выбери Number. Ожидаемо: строка rating с иконкой числа.
  3. Тип общий. Открой Сталкер (1979), снова Ctrl+;, имя rating, значение 9. Ожидаемо: иконка уже числа — ты тип не выбирал, он пришёл из Солярис.
  4. Все свойства хранилища. Ctrl+P — это Command palette, список всех команд Obsidian.[команды] Набери properties и выбери команду, которая показывает все свойства (All properties). Ожидаемо: 22 свойства (21 было + твой rating). Отсортируй по частоте (frequency — сколько раз встречается): первым будет type, он есть в 6 заметках.[All properties]
  5. Поиск по свойству. В All properties нажми на director — откроется поиск с уже набранным запросом. Ожидаемо: 2 заметки, Сталкер (1979) и Солярис (1972). Синтаксис этого запроса разберём в уроке 0004.
  6. Переименование. Правый клик по where → переименуй в location. Открой Пикник на обочине: там теперь location: Полка 2 — Obsidian поменял все 3 файла сразу.[All properties] Переименуй обратно в where.
  7. Псевдоним. В Солярис (1972), в разделе «Мой комментарий», набери [[Tarkovsky. Ожидаемо: подсказка со значком изогнутой стрелки → Enter → [[Тарковский|Tarkovsky]]. Псевдонимы заданы в Люди/Тарковский.
  8. Вложенный тег. Ctrl+P → набери tags → открой Tags view (список всех тегов хранилища). Ожидаемо: тег кино, а под ним советское — он стоит у Сталкер и Солярис. Рядом без вложения: фантастика, пересмотреть.[теги]
  9. Как показывать свойства. Settings → Editor → Properties in document: Visible (таблица, по умолчанию), Hidden (скрыть), Source (показать как YAML-текст).[свойства] Попробуй Source, потом верни Visible.

Хранилище лежит в git-репозитории курса: твои правки будут видны в git status. Вернуть всё как было: git checkout -- practice-vault.

9. Что это значит для Kolnatun

Ты не пишешь свойства руками — их пишет Claude. Твоя задача — сказать, какие. Свойства SetErrorObject.md по типам:

#СвойствоТипЗачем
1type, kind, projectTextслой и вид страницы: entity / function / BL
2sourceTextпуть к исходнику
3lineNumberстрока в исходнике
4used_byListкакие калькуляторы используют; один калькулятор — один пункт
5parentText (ссылка)страница-контейнер "[[mdlGeneral.bas]]"

Правила, которые стоит дать Claude для любой вики:

  1. Одно имя — один тип во всех заметках (line всегда число).
  2. Несколько значений — List, по одному на строку, а не "AcademicEnd, SalaryCalc" одной строкой.
  3. Ссылки в свойствах — в кавычках: "[[…]]".
  4. Даты — YYYY-MM-DD. Да/нет — true / false.
  5. Без вложенных свойств и без Markdown в значениях.
  6. tags и aliases, а не tag / alias; теги без # и без пробелов внутри тега.

Именно по этим свойствам потом работают поиск (0004), граф (0005), Dataview (0006) и Bases (0007).
