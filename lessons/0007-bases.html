Bases: таблица, которую можно править

Dataview (урок 0006) показывает таблицу по свойствам, но только читает. Bases — встроенный в Obsidian плагин: та же таблица собирается мышкой, а значение в ячейке можно поменять, и оно запишется в свойство заметки.

Цель урока. Собрать в practice-vault базу «Медиатека»: таблица с годом, статусом и местом хранения, сортировка, группы, формула, итог по столбцу, второй вид карточками — и вставить её в заметку. Потом прочитать .base-файл как текст и перевести на Bases запрос Kolnatun из урока 0006.

1. Что такое Bases

Bases — «core plugin (встроенный плагин), который даёт базоподобные виды твоих заметок»: в базе можно смотреть, править, сортировать и фильтровать файлы и их свойства.[bases]

#ФактЧто это значит
1Core plugin — встроенный, ставить не надов отличие от Dataview, нет Restricted mode и стороннего кода. Включается в Settings → Core plugins → Bases[core]
2данные — в твоих заметках«все данные Bases хранятся в локальных Markdown-файлах и их свойствах»[bases]. База — это только вид: какие файлы показать и как
3вид хранится в файле .baseэто текст в формате YAML (тот же, что у свойств, урок 0002). Его можно открыть и прочитать как текст, а можно вставить в заметку блоком ```base[синтаксис]
4правка в таблице меняет заметкуглавное отличие от Dataview, который «только читает». Поменял статус в ячейке — поменялось свойство status в файле. Отмена — Ctrl+Z[table]

Bases появились в Obsidian 1.9 (виды Table и Cards), List — в 1.10, Kanban — в 1.14.[views] Если в меню вида нет какого-то варианта — версия Obsidian старше.

2. Слова урока

#СловоЧто это
1Base (база)файл .base: фильтры + формулы + один или несколько видов
2View (вид)одна раскладка базы: Table, List, Cards, Kanban, Map. У каждого вида свои сортировка, группы, столбцы, фильтры. Пример: база «Книги» с видами «Читаю» и «Прочитано недавно»[views]
3Filter (фильтр)условие, какие файлы показать. База без фильтров показывает все файлы хранилища[views]
4Formula (формула)вычисляемое свойство: живёт в .base, в заметки не пишется. formula.имя[formulas]
5Summary (итог)строка под столбцом таблицы: сумма, среднее, min, max, сколько заполнено[table]

5. Фильтры

В меню Filter два раздела:[views]

  • All views — фильтр для всех видов базы. Сюда — «что вообще входит в базу»: например, только папка Медиатека.
  • This view — только для открытого вида: «из медиатеки — только фильмы». Оба фильтра действуют вместе, как «и».[синтаксис]

Условие — три части: свойство → оператор (список зависит от типа свойства: текст, число, дата) → значение. Несколько условий объединяет conjunction (связка):

#В менюЗначитВ тексте .base
1All the following are trueвсе условия — «и»and:
2Any of the following are trueхотя бы одно — «или»or:
3None of the following are trueни одного — «кроме»not:

Filter group (группа фильтров) — связка внутри связки, как скобки в поиске: «фильм и (смотрел или хочу пересмотреть)». Кнопка с кодом </> открывает advanced filter editor — тот же фильтр текстом; там доступны функции, которых нет в меню.[views]

Язык фильтров и формул

Похож на Dataview, но не тот же. Главные отличия:[синтаксис][функции]

#НужноDataview (0006)Bases
1папка с подпапкамиFROM "Медиатека/Фильмы"file.inFolder("Медиатека/Фильмы")
2тег с подтегамиFROM #киноfile.hasTag("кино") — подтеги кино/советское тоже
3равноtype = "film"type == "film" — два знака равенства
4и / или / неAND, OR, !&&, ||, ! — или пункты списка под and: / or: / not:
5есть элемент в спискеcontains(used_by, "AcademicEnd")used_by.contains("AcademicEnd") — функция пишется через точку после значения
6сколько элементовlength(used_by)used_by.length — без скобок, это поле
7свойство естьWHERE duplicate_offile.hasProperty("duplicate_of")
8изменено за неделюfile.mtime >= date(today) - dur(7 days)file.mtime > now() - "1 week"
9заметка, где стоит запросthisthis — но см. ниже
Нет FROM — есть фильтр. Справка прямо говорит: «по умолчанию база включает каждый файл хранилища; нет from, как в SQL или Dataview».[синтаксис] Каждый — значит и картинки, .canvas, .mmd, .html. В Kolnatun рядом с заметками лежат диаграммы и HTML — для таблицы заметок добавь file.ext == "md".
Путь в file.inFolder — через /, без *. Как в Dataview: "Медиатека/Фильмы", подпапки берутся сами. Справка называет аргумент «folder name» и показывает только пример из одной папки (file.inFolder("notes")); надёжно — путь от корня хранилища. Найдёт ли file.inFolder("Фильмы") вложенную папку — открытый вопрос, шаг 3 практики.[функции]
this зависит от того, где открыта база. Открыта как файл — this = сам .base-файл. Вставлена в заметку — this = эта заметка. В боковой панели — this = заметка, открытая в главной области; поэтому file.hasLink(this.file) в боковой панели работает как Backlinks.[синтаксис]

6. Свойства, формулы, итоги

В базе три вида свойств:[синтаксис]

#ВидПишешьОткуда
1Note propertiesyear или note.yearYAML заметки (урок 0002); есть только у .md
2File propertiesfile.name, file.folder, file.path, file.ext, file.size, file.ctime, file.mtime, file.tags, file.links, file.backlinksесть у любого файла
3Formula propertiesformula.ageформула из этой базы

Формула: Properties → Add formula → имя → выражение в поле Formula. Редактор подсказывает функции и ставит зелёную галочку, когда выражение верное.[formulas] Примеры для медиатеки:

#ФормулаЧто даёт
1today().year - yearсколько лет фильму или книге: today() — сегодня, .year — год даты
2cast.lengthсколько актёров в списке cast
3if(status == "смотрел", "✓", "")галочка у просмотренных: if(условие, если да, если нет)

Формула не пишется в заметки: она хранится в .base и считается при показе. Формула не может ссылаться сама на себя, даже через другую формулу.[formulas]

Итог: правый клик по заголовку столбца → Summarize… → Average, Min, Max, Sum, Median… для чисел; Earliest / Latest для дат; Empty / Filled / Unique — для любых. Итог считается по видимым строкам и принадлежит виду, а не базе.[table]

8. Файл .base как текст

Обычно базу правят мышкой, но под ней — YAML, и его можно прочитать (а Claude — написать). Пять разделов верхнего уровня:[синтаксис]

filters:                       # 1. для всех видов (All views)
  and:
    - file.inFolder("Медиатека")
    - file.ext == "md"
formulas:                      # 2. вычисляемые свойства
  age: "today().year - year"
properties:                    # 3. настройки свойств: подписи столбцов
  formula.age:
    displayName: "Лет"
summaries:                     # 4. свои формулы итогов (необязательно)
  avgRounded: "values.mean().round(1)"
views:                         # 5. виды
  - type: table
    name: "Всё"
    order:                     #    столбцы по порядку
      - file.name
      - year
      - status
      - where
      - formula.age
    summaries:
      year: Min
  - type: cards
    name: "Фильмы"
    filters:                   #    фильтр только этого вида (This view)
      and:
        - 'type == "film"'
Кавычки в кавычках. Условие с текстом в кавычках — type == "film" — целиком берут в одинарные кавычки: 'type == "film"'. Справка: «вложенные кавычки нужны, чтобы включить текст в поле YAML».[синтаксис] Отступы — пробелами, как в свойствах (урок 0002).

9. Bases или Dataview?

#ЧтоDataviewBases
1установкаcommunity plugin, Restricted modeвстроен (core plugin)
2как собиратьписать код DQLмышкой; текст .base — по желанию
3править значения в таблиценет, только чтениеда — меняет заметки
4откуда берётFROM; без него — все заметкивсе файлы хранилища, сужают фильтры
5группыGROUP BY + rows: можно считать по группе (length(rows))Group by — одно свойство; итог по группе — в её заголовке
6строка на элемент спискаFLATTENв справке нет
7видыLIST, TABLE, TASK, CALENDARTable, List, Cards, Kanban, Map; несколько видов в одной базе
8экспорт—копировать в таблицу, CSV (меню Results)

Правило: смотреть и править медиатеку — Bases. Сводки с подсчётом по группам, как length(rows) в INDEX.md Kolnatun, — Dataview.

14. Что это значит для Kolnatun и LLM-wiki

#Правило для схемыПочему
1в базах для Kolnatun — фильтр file.ext == "md"база берёт все файлы: без него в таблицу попадут .mmd и .html
2свойства, которые ведёт Claude (used_by, source, line), руками в таблице не правитьправка в ячейке меняет файл; Backspace по выделению стирает значения. Для Kolnatun Bases — окно для чтения
3одинаковые значения (kind: function, не Function)== сравнивает точно; Group by и Kanban заведут отдельную колонку на каждый вариант написания
4списки — List (урок 0002)used_by.contains("AcademicEnd"), used_by.length > 1 работают со списком
5медиатека — в Bases, Kolnatun INDEX — в Dataviewмедиатеку удобно править и смотреть карточками; INDEX считает по группам (length(rows))

Пример: первая таблица INDEX.md («функции, которые использует больше одного калькулятора») на языке Bases:

filters:
  and:
    - file.inFolder("calculators/shared")
    - file.ext == "md"
    - used_by.length > 1
views:
  - type: table
    name: Общий код
    order:
      - file.name
      - type
      - kind
      - source
      - used_by
