Поиск

Поиск Obsidian — маленький язык запросов: по тексту, по имени и пути файла, по тегам и по свойствам. Тот же язык работает в фильтре графа (урок 0005), поэтому здесь его основа.

Цель урока. Одной строкой найти «все фильмы на HDD-2TB-01», «все функции, которые использует AcademicEnd» или «всё, кроме служебных папок» — и понимать, почему запрос нашёл именно это.

1. Где искать

Панель Search — в левой боковой панели. Открыть: Ctrl+Shift+F. Если перед этим выделить текст в заметке, поиск откроется уже с ним.[поиск]

Что поиск просматривает: текст ищется только в заметках (.md) и холстах (.canvas). Но file: и path: находят любой файл хранилища — и картинки, и .mmd, и .html.[поиск]

2. Слова и логика

#ПишешьНаходит
1Тарковский зимойзаметки, где есть оба слова (в любом месте, в любом порядке)
2"Пикник на обочине"точную фразу — в кавычках
3Сталкер OR Солярисхотя бы одно из слов. OR — заглавными
4Тарковский -Солярисс первым словом, но без второго. Минус вплотную к слову
5фантастика (Сталкер OR Пикник)скобки задают порядок, как в арифметике
6-(Kolnatun README)минус перед скобками убирает всю группу

Источник: Obsidian Help → Search, разделы Search terms.

Регистр по умолчанию не важен: тарковский найдёт «Тарковский». Включить различие — кнопка Match case в панели поиска или оператор match-case:.[поиск]

3. Операторы: где именно искать

Оператор — слово с двоеточием перед запросом. Он сужает, где искать.[поиск]

#ОператорИщетПример
1file:в имени файлаfile:Сталкер
2path:в пути: папки + имя файла. path:Сталкер находит Сталкер (1979), хотя такой папки нетpath:Медиатека/Фильмы
3content:только в тексте заметкиcontent:"держит"
4tag:тег (раздел 4)tag:кино
5line:( )слова в одной строкеline:(Медленный держит)
6section:( )слова в одном разделе — между заголовкамиsection:(Цитата Счастье)
7block:( )слова в одном блоке (абзац, пункт списка)block:(Счастье даром)
8task: / task-todo: / task-done:в задачах - [ ]: любых / незакрытых / закрытыхtask-todo:пересмотреть
9match-case: / ignore-case:с учётом / без учёта регистраmatch-case:BL
Привычки Windows — два правила.
  1. Пути — через /: path:Медиатека/Фильмы. Обратный слеш \ не сработает.
  2. * — не шаблон. file: и path: и так ищут часть строки: file:Стал найдёт «Сталкер (1979)». Звёздочка будет искаться как обычный символ.
Нужно именно «начинается с» — регулярное выражение (раздел 6): file:/^Стал/.
Оператор действует на одно слово — или на группу в скобках. path:Kolnatun OR Хранилища — это «путь содержит Kolnatun» или «слово Хранилища в тексте». Второе слово оператор не получает. Чтобы оператор относился к нескольким словам, их берут в скобки сразу после двоеточия. Справка говорит, что так умеют «некоторые операторы», и приводит task:(call OR email).[поиск] path: на практике тоже умеет: Explain search term для запроса ниже показывает «Excluding → Match file path → Match any of: Kolnatun, Хранилища».
#ЗапросЧто значит
1-(path:Kolnatun OR Хранилища)ошибка: убирает папку Kolnatun и заметки со словом «Хранилища» в тексте, а папку Хранилища оставляет
2-(path:Kolnatun OR path:Хранилища)убрать обе папки — оператор у каждого слова
3-(path:(Kolnatun OR Хранилища))то же, короче — оператор на группу
4-path:Kolnatun -path:Хранилищато же, без OR: «не там и не там»

4. Теги: tag: ищет от корня

tag или tags? В поиске оператор пишется в единственном числе: tag:.[поиск] Во множественном числе, tags, называется свойство в YAML (урок 0002); старое имя tag там устарело с версии 1.9.[свойства] Запомнить так: в YAML у заметки много тегов, а запрос ищет один тег.

tag: точнее простого поиска: он не смотрит в блоки кода. Писать можно с # и без: tag:#кино = tag:кино.[поиск] Для вложенных тегов (урок 0002) правило одно — от корня вниз:

#ЗапросТег кино/советское найдётся?
1tag:кинода — родитель находит всё, что под ним[теги]
2tag:кино/советскоеда — полный тег
3tag:советскоенет — вложенная часть сама по себе не ищется. Справка: «tag:#work не найдёт #myjob/work»[поиск]

Вывод для схемы: если «советское» нужно искать само по себе (и фильмы, и книги) — ставь отдельный тег советское, а не только кино/советское.

5. Поиск по свойствам

#ЗапросНаходит
1[aliases]заметки, у которых есть свойство aliases
2[type:film]заметки, где значение type — film
3[used_by:null]свойство есть, но пустое — в Kolnatun это «функция, которую уже никто не использует»
4[status:смотрел OR "хочу пересмотреть"]одно из значений; внутри скобок работают OR, кавычки, regex
5[year:<1975]сравнение чисел: < меньше, > больше

Источник: Obsidian Help → Search, разделы Search properties и Comparison operators.

Для списков (List) значение сравнивается с элементами списка: [used_by:AcademicEnd] должен найти функцию, у которой AcademicEnd — один из калькуляторов в used_by (в справке это не расписано; проверь в шаге 9). Найдёт ли [where:HDD] значение HDD-2TB-01 (часть значения, а не всё) — справка не уточняет; проверь сам в шаге 4 практики.

Справка и практика расходятся. По справке [aliases] находит файлы со свойством aliases.[поиск] На практике в practice-vault он находит 3 файла, а не 2: Солярис и Тарковский (свойство) плюс README, где слово aliases есть просто в тексте. Поэтому имя свойства в скобках — не строгий фильтр. Если результат нужен точным, добавь значение ([aliases:Solaris]) или исключи лишнее ([aliases] -file:README). Песочница ниже этого не повторяет и показывает 2.

6. Регулярные выражения

Регулярное выражение (regex) — шаблон текста. В поиске пишется между двумя / и работает и с операторами.[поиск]

#ЗапросНаходит
1/\d{4}-\d{2}-\d{2}/дату вида 2026-10-06 (\d — цифра, {4} — 4 раза)
2file:/^Стал/имя файла начинается с «Стал» (^ — начало)
3path:/\(19[67]\d\)/фильмы 1960–1979 по году в скобках в имени

Для начала хватит ^ (начало), $ (конец), \d (цифра), . (любой символ). Скобки и точку как обычный символ экранируют \: \(, \..

7. Полезные мелочи панели

#ЧтоГдеЗачем
1Explain search termнастройки поискаObsidian расписывает словами, как понял твой запрос — лучший способ найти ошибку
2Сортировкапо имени или по времени изменения / создания«что Claude поменял последним» — сортировка по Modified time
3Copy search resultsменю ⋯ рядом с числом результатовсписок найденного одной кнопкой
4Встроенный поискблок ```query в заметкерезультаты поиска прямо в заметке, обновляются сами

Источник: Obsidian Help → Search.

«0 results», а список не пустой. Если в запросе только исключения (например -path:Kolnatun -path:Хранилища), над списком может стоять 0 results, хотя файлы ниже перечислены. Справка этого не объясняет. Похоже, счётчик считает совпадения в тексте, которые можно подсветить, а у запроса из одних минусов их нет. Верить в этом случае надо списку, а не числу.

Встроенный поиск пишется так — три обратных апострофа, слово query, запрос, три апострофа:

```query
[type:film] tag:кино
```

Для LLM-wiki это лёгкая замена Dataview, когда нужен просто список: «все страницы с [used_by:SalaryCalc]» на странице калькулятора.

8. Практика: песочница

Это 9 заметок учебного хранилища practice-vault плюс два файла-не-заметки для примера (.jpg и .mmd — в practice-vault их нет). Справа от имени — type и tags. Песочница понимает file:, path:, content:, tag:, [свойство], [свойство:значение], [свойство:a OR b], path:(a OR b), -, OR, скобки, кавычки. Простые слова и content: ищут в тексте заметки (без свойств). line:, section:, regex и сравнения < > — только в настоящем Obsidian.

Если ответ неверный, проверка скажет, что лишнее, чего не хватает и почему (слеши, *, условие, которое ничего не нашло, вложенный тег).
