1. Проблема: каждый раз с нуля

Обычная работа LLM с документами — RAG (retrieval-augmented generation): загружаешь файлы, на каждый вопрос модель ищет подходящие куски и собирает ответ. Работает, но знание не накапливается: сложный вопрос по пяти документам — и модель снова ищет и склеивает те же куски.[Карпати]

Идея LLM-wiki: модель постепенно строит и поддерживает постоянную вики — набор связанных Markdown-файлов между тобой и источниками. Новый источник она не просто индексирует, а встраивает: обновляет страницы сущностей, пересматривает сводки, отмечает, где новые данные противоречат старым. Знание «компилируется» один раз и потом поддерживается в актуальном виде.[Карпати]

#RAGLLM-wiki
1Когда модель «понимает» источникина каждом вопросе зановоодин раз, при добавлении источника
2Перекрёстные ссылки, противоречияищутся каждый разуже записаны в страницах
3Что остаётся после вопросаответ в истории чатахороший ответ можно сохранить новой страницей

2. Роли: кто что делает

#КтоДелает
1Тыподбираешь источники, направляешь анализ, задаёшь вопросы, решаешь, что всё это значит. Вики сам не пишешь (или почти не пишешь).
2LLM (у нас — Claude Code)всё остальное: сводки, перекрёстные ссылки, раскладка по страницам, учёт.
3Obsidianместо, где ты читаешь результат: идёшь по ссылкам, смотришь граф, читаешь обновлённые страницы.

Формула Карпати: «Obsidian — это IDE, LLM — программист, вики — кодовая база». Он держит агента открытым с одной стороны экрана, Obsidian — с другой, и смотрит правки в реальном времени.[Карпати]

Почему это работает: скучная часть вики — не чтение и не мысли, а учёт (обновить ссылки, поддержать сводки, заметить противоречие). Люди бросают вики, потому что учёт растёт быстрее пользы. LLM не устаёт и может поправить 15 файлов за проход.[Карпати]

4. Три операции

#ОперацияЧто происходитKolnatun
1Ingest (загрузить)кладёшь новый источник в raw и просишь обработать. LLM читает, обсуждает с тобой главное, пишет страницу-сводку, обновляет index, страницы сущностей и понятий, дописывает log. Один источник может задеть 10–15 страниц. Карпати предпочитает по одному источнику и следить.извлечение калькулятора, шаг 10 (запланирован в shared/README.md): для каждого внешнего вызова найти или создать страницу в shared/entities и добавить строку калькулятора
2Query (спросить)задаёшь вопрос. LLM ищет страницы (сначала по index), читает, отвечает со ссылками. Главное: хороший ответ сохраняют обратно в вики новой страницей, чтобы он не пропал в истории чата.«что общего у AcademicEnd и SalaryCalc?» → ответ стоит сохранить в shared/concepts
3Lint (проверить)периодическая проверка здоровья: противоречия между страницами, устаревшие утверждения, страницы-сироты без входящих ссылок, понятия без своей страницы, недостающие ссылки, пробелы в данных.scaffold/KNOWLEDGE-LINT-START-PROMPT.md → отчёт shared/lint-report.md; только отчёт, никаких правок

Операции — Карпати, раздел Operations. Kolnatun — из shared/README.md и scaffold/.

5. Два служебных файла: index и log

#ФайлЧто внутриЗачем
1index.mdкаталог: каждая страница — ссылка + одна строка описания, по категориям (сущности, понятия, источники). Обновляется при каждом ingest.отвечая на вопрос, LLM сначала читает index, потом нужные страницы. Карпати: хватает примерно до ~100 источников и сотен страниц — без отдельной поисковой системы.
2log.mdжурнал по времени, только дописывается: ingest, query, lint. Заголовок каждой записи в одном формате: ## [2026-10-06] ingest | Названиеистория вики; LLM видит, что делали недавно. Последние 5 записей: grep "^## \[" log.md | tail -5

Раздел Indexing and logging.

В Kolnatun роль index играет shared/INDEX.md — там ещё и живые таблицы Dataview. А scaffold/extraction-log.md — журнал решений процесса, не журнал ingest. Журнала «что и когда загружено в shared» у тебя пока нет — кандидат в схему.

11. Теперь в Obsidian и Claude Code

Для этого урока есть отдельное хранилище — маленькая готовая LLM-wiki медиатеки: practice-llm-wiki (рядом с practice-vault). В ней уже сделаны два ingest (Сталкер, Солярис), третий источник ждёт тебя.

Метка у шага — в каком хранилище его делать: practice-llm-wiki учебная вики, learn-obsidian/practice-llm-wiki — в Obsidian и в терминале с Claude Code. Это не practice-vault из уроков 0001–0007: здесь другие заметки, и числа из тех уроков сюда не подходят. Рабочее хранилище Kolnatun в этом уроке не трогаем.

  1. practice-llm-wikiОткрой. Obsidian → Vault profile (слева внизу) → Manage vaults → Open folder as vault → папка C:/_repos/github/segal.st/teach/learn-obsidian/practice-llm-wiki (урок 0005). Ожидаемо: открылось отдельное окно с хранилищем practice-llm-wiki.
  2. practice-llm-wikiНайди слои. raw/ — 3 заметки, wiki/ — 6 страниц, CLAUDE.md — схема, плюс index.md и log.md. Прочитай CLAUDE.md — это то, что Claude прочтёт первым.
  3. practice-llm-wikiСвязи. Открой wiki/Люди/Тарковский, посмотри панель Backlinks. Ожидаемо: в Linked mentions — страницы, где есть [[Тарковский]] (фильмы, index); в Unlinked mentions — места, где «Тарковский» написан просто текстом (raw-заметки, log). Raw — не вики, ссылки там и не нужны.
  4. practice-llm-wikiСироты. Открой граф, в Filters выключи Orphans. Ожидаемо: пропадут 5 заметок без единой ссылки — CLAUDE.md, log.md, README.md (служебные, это нормально), 2026-10-05 Пикник на обочине (ещё не загружен) и Донатас Банионис — это находка lint: страница вики, на которую никто не ссылается.
  5. practice-llm-wikiLint глазами. Сверь с правилами CLAUDE.md. Ожидаемо найдёшь: (а) Донатас Банионис — сирота, нет в index.md, нет sources и раздела «Источники»; (б) ссылка [[Стругацкие]] ведёт на страницу, которой нет: файла Стругацкие.md в хранилище нет — в графе это отдельная точка, её прячет Filters → Existing files only (урок 0005); (в) в Солярис (1972) «Донатас Банионис» написан простым текстом, а схема требует ссылку [[…]] на каждую страницу вики — открой Донатас Банионис, Backlinks → Unlinked mentions: там будет Солярис. Находки (а) и (в) связаны: была бы ссылка — не было бы сироты.
  6. practice-llm-wikiLint руками Claude. В терминале: cd C:/_repos/github/segal.st/teach/learn-obsidian/practice-llm-wiki (прямые / работают и в Windows), запусти claude и напиши: lint. Ожидаемо: отчёт с находками (а)–(в), без правок файлов — так велит схема. Если Claude что-то пропустил или нашёл лишнее — сверь с CLAUDE.md: схема решает, что считается ошибкой.
  7. practice-llm-wikiIngest. Там же: ingest raw/заметки/2026-10-05 Пикник на обочине.md. Держи Obsidian открытым рядом. Ожидаемо: Claude коротко обсудит источник, создаст wiki/Книги/Пикник на обочине и, скорее всего, wiki/Люди/Стругацкие (ссылка из (б) начнёт вести на страницу), обновит Сталкер, Экранизация, index.md и добавит запись в log.md. Точный набор страниц решит Claude — сверь его с правилами схемы.
  8. practice-llm-wikiQuery с сохранением. Спроси: какие фильмы в вики сняты по книгам и чем они отличаются от книг? сохрани ответ как страницу. Ожидаемо: ответ со ссылками и новая страница в wiki/Понятия/.
  9. practice-llm-wikiЧто изменилось. Выйди из Claude (/exit) — терминал остаётся в папке practice-llm-wiki. git status . и git diff . — все правки Claude по файлам (точка = эта папка). Ожидаемо: изменены index.md, log.md и страницы из шага 7, новые файлы — в списке Untracked. Вернуть исходное состояние: git checkout -- . и git clean -fd .
