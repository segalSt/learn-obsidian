Dataview: первая таблица

Поиск (урок 0004) отвечает списком файлов. Dataview отвечает таблицей: «фильм — год — где лежит», «функция — строка — кто использует». Таблица живёт прямо в заметке и сама обновляется, когда меняются свойства.

Цель урока. Читать и править запросы, которые уже стоят в Kolnatun (shared/INDEX.md, страницы-контейнеры), и написать свою таблицу для медиатеки: «все фильмы на HDD-2TB-01, по годам».

1. Что такое Dataview

Dataview — «живой индекс и движок запросов» по твоему хранилищу: читает свойства заметок и показывает их списком, таблицей, задачами или календарём.[dataview] Три вещи, которые надо знать сразу:

#ФактЧто это значит
1Dataview — community plugin (плагин сообщества), не встроенный в Obsidianего надо установить и включить (раздел 2). Встроенная замена — Bases, урок 0007[bases]
2Dataview только читает«не предназначен для правки заметок и всегда оставляет их нетронутыми» — кроме галочек задач в запросах TASK[dataview]. Сломать данные запросом нельзя
3видит только то, что проиндексировалсвойства, теги, ссылки, задачи, списки, поля file.*[dataview]. Обычный текст абзаца — нет: для текста есть поиск

Языков запросов у Dataview три: DQL (Dataview Query Language — язык этого урока), inline DQL (одно значение прямо в строке текста, раздел 8) и DataviewJS (запросы на JavaScript — гибче всего, но сложнее; в этом курсе не нужен).[dataview]

2. Установка

Community plugins — плагины, которые пишут не разработчики Obsidian. Справка предупреждает: они «запускают сторонний код от твоего имени, который потенциально может навредить».[плагины] Поэтому по умолчанию они выключены режимом Restricted mode.

  1. Settings → Community plugins → выключить Restricted mode (кнопка «Turn on community plugins»).
  2. Browse → найти Dataview → Install.
  3. Enable — сразу после установки или позже в Settings → Community plugins → Installed plugins. Установить ≠ включить: без Enable плагин не работает.[плагины]

Настройки хранятся в папке .obsidian внутри хранилища — «все файлы настроек твоего хранилища».[настройки] Поэтому плагин ставят и включают в каждом хранилище: в шаге 1 практики — в practice-vault.

3. Первый запрос

Запрос DQL пишется в блоке кода с языком dataview — три обратных апострофа, слово dataview, запрос, три апострофа:[структура]

```dataview
LIST
FROM "Медиатека"
```

В режиме чтения (Ctrl+E, урок 0001) на месте блока появится список ссылок: Пикник на обочине, Солярис (1972), Сталкер (1979). В Live Preview результат обычно тоже виден, пока курсор вне блока; курсор внутри — видишь код.

Структура любого запроса:[структура]

#ЧастьОбязательна?Сколько раз
1Query type (тип запроса): LIST, TABLE, TASK, CALENDARда, всегда первой1
2FROM — откуда брать заметкинет; без него — всё хранилище0 или 1, сразу после типа
3Data commands (команды): WHERE, SORT, GROUP BY, FLATTEN, LIMITнетсколько угодно, в любом порядке
Сверху вниз, строка за строкой. Это не SQL: запрос «выполняется сверху вниз, строка за строкой, больше похоже на программу».[vs SQL] Каждая команда получает результат предыдущей. Поэтому LIMIT 1, а потом SORT year DESC — это «взять одну любую заметку и отсортировать её», а не «самую новую».[команды]

4. Типы запросов

#ТипЧто показываетПример
1LISTсписок ссылок на заметки; можно добавить одно значение рядомLIST year FROM "Медиатека" — рядом с каждой ссылкой год
2TABLEтаблица: первый столбец — заметка (File), дальше столбцы через запятуюTABLE year, status FROM "Медиатека"
3TASKзадачи - [ ] из заметок; отметка галочки меняет файлTASK WHERE !completed
4CALENDARкалендарь: точка на дате из поляCALENDAR file.ctime

Источник: Dataview → Query Types.

Две добавки к TABLE:

  • AS — своё имя столбца: TABLE year AS "Год", status AS "Статус". Имя с пробелом — в кавычках.
  • WITHOUT ID — убрать первый столбец File. Так переименовывают и его: TABLE WITHOUT ID file.link AS "Фильм", year AS "Год".[типы]

5. FROM: откуда брать

#ПишешьБерёт
1FROM "Медиатека"папку и все подпапки. Путь — в кавычках
2FROM "Медиатека/Фильмы/Сталкер (1979)"один файл
3FROM #кинотег и все его подтеги (#кино/советское тоже)
4FROM [[Пикник на обочине]]заметки, которые ссылаются на Пикник (как Backlinks, урок 0003)
5FROM outgoing([[Тарковский]])заметки, на которые ссылается Тарковский
6FROM #кино and -"Медиатека/Книги"сочетание: and, or, минус = «кроме»

Источник: Dataview → Data Commands → FROM.

Путь — от корня хранилища, через /, без *.
  1. В отличие от path: в поиске (там — любая часть пути), FROM "папка" — это путь от корня хранилища. В Kolnatun так и написано: FROM "calculators/shared/entities", полный путь. В practice-vault FROM "Фильмы" ничего не найдёт — нужно FROM "Медиатека/Фильмы".
  2. Разделитель — /. Скопированный из Проводника Windows путь с \ не сработает.
  3. * не нужна и не шаблон: папка и так берётся со всеми подпапками.
  4. Без кавычек нельзя: FROM Медиатека — ошибка; кавычки отличают папку от тега и ссылки.

6. WHERE: фильтр по свойствам

Все свойства из YAML (урок 0002) — сразу поля Dataview, по имени: year, status, used_by.[метаданные] WHERE условие оставляет только заметки, где условие истинно.[команды]

#УсловиеЗначит
1type = "film"равно. Текст — в кавычках: без них film — это имя поля, а не слово
2status != "смотрел"не равно
3year < 1975, >, <=, >=сравнение; числа без кавычек
4a AND b, a OR b, !aи / или / не; скобки группируют
5WHERE duplicate_ofполе есть и не пустое — как [duplicate_of] в поиске
6contains(used_by, "AcademicEnd")для списка — есть такой элемент; для текста — есть такая часть. С учётом регистра; без учёта — icontains
7length(used_by) > 1в списке больше одного элемента
8file.mtime >= date(today) - dur(1 day)изменено за последние сутки: date() — дата, dur() — длительность

Источники: Expressions, Functions, Data Commands.

Поля, которые есть у каждой заметки

Кроме твоих свойств, Dataview сам добавляет implicit fields (неявные поля) file.*:[file.*]

#ПолеЧто в нём
1file.nameимя файла, как в боковой панели
2file.linkссылка на файл — для столбца «Фильм» в TABLE WITHOUT ID
3file.folder / file.pathпапка / полный путь с именем
4file.ctime / file.mtimeсоздан / изменён (дата и время); file.cday / file.mday — только дата
5file.tagsвсе теги заметки
6file.inlinks / file.outlinksвходящие / исходящие ссылки
7file.aliasesпсевдонимы
Свойство с именем команды. У фильмов есть свойство where (урок 0002). Но WHERE — команда Dataview, и WHERE where = "HDD-2TB-01" не сработает. Для таких имён есть «фальшивое» поле row: row.where, row.from.[faq] Правильно: WHERE row.where = "HDD-2TB-01". Имя с пробелом — так же: row["имя с пробелом"].
Пустые значения. Документация предупреждает: сравнение с отсутствующим полем может дать неожиданный результат, и советует сначала проверить, что поле есть: WHERE year AND year < 1975.[выражения] В шаге 4 практики проверь сам, что будет без year AND.

7. Сортировка, группы, развёртка

#КомандаЧто делаетПример
1SORT поле ASC / DESCпо возрастанию / убыванию; при равенстве — по второму полюSORT year DESC, file.name ASC
2LIMIT nне больше n результатовLIMIT 5
3GROUP BY полеодна строка на каждое значение поля; заметки группы — в списке rowsGROUP BY type
4FLATTEN поленаоборот: одна строка на каждый элемент спискаFLATTEN authors

Источник: Dataview → Data Commands.

После GROUP BY в столбцах пишут не поле заметки, а то, что есть у группы: length(rows) — сколько заметок в группе; rows.file.link — их ссылки (Dataview сам берёт поле из каждой заметки списка).[команды]

```dataview
TABLE length(rows) AS "Сколько", rows.file.link AS "Заметки"
WHERE type
GROUP BY type
```

8. Inline: одно значение в тексте

Inline DQL — выражение в обычном коде строки (одинарные апострофы) с префиксом =. Показывает ровно одно значение, без типов запросов и команд.[inline]

#Пишешь в текстеВидишь
1`= this.file.name`имя этой заметки. this — заметка, в которой стоит запрос
2`= date(today)`сегодняшнюю дату
3`= [[Солярис (1972)]].year`свойство другой заметки: 1972

this работает и в обычном запросе: в Kolnatun source = this.source значит «тот же исходник, что у этой страницы» (раздел 10).

У Dataview есть и свой синтаксис полей прямо в тексте — inline fields: Режиссёр:: [[Тарковский]], с двумя двоеточиями.[метаданные] Это синтаксис Dataview, а не свойства Obsidian: свойства — это YAML в начале заметки (урок 0002), и именно их показывают All properties, поиск [свойство] и Bases.[свойства] Для Kolnatun и медиатеки держи данные в YAML-свойствах — их читают все инструменты.

14. Что это значит для Kolnatun и LLM-wiki

#Правило для схемыЧто даёт Dataview
1данные — в YAML-свойствах, не в inline fieldsодни и те же свойства читают поиск, граф, Dataview и Bases
2не называть свойства как команды DQL (where, from, sort)не нужен row.where; для медиатеки удобнее location — но переименование трогает все заметки (All properties → Rename, урок 0002)

4связи-списки — List (used_by)contains(), length(), FLATTEN работают со списками
