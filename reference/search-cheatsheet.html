Поиск и фильтр графа

Один язык для поиска (Ctrl+Shift+F) и для Graph view → Filters → Search files.

Операторы

#ОператорПримерЗначит
1path:path:shared/entitiesпуть содержит строку
2file:file:glossaryимя файла содержит строку
3content:content:"nek_zikui"только текст заметки
4tag:tag:киноесть тег. Вложенные — только от корня: tag:кино находит кино/советское, tag:советское — нет
5[prop][used_by]свойство есть
6[prop:value][kind:method]свойство с этим значением; у списка — один из элементов
7[prop:null][used_by:null]свойство есть, но пустое
8[prop:a OR b][status:смотрел OR "хочу пересмотреть"]одно из значений
9[prop:<n] / [prop:>n][year:<1975]сравнение чисел
10line:( )line:(CalcNek mone)слова в одной строке
11section:( )section:(Relation MasHazmai)слова в одном разделе (между заголовками)
12block:( )block:(Счастье даром)слова в одном блоке
13task-todo:task-todo:пересмотретьв незакрытых задачах; task: — в любых, task-done: — в закрытых
14match-case:match-case:BLс учётом регистра (по умолчанию регистр не важен)
15/regex/file:/^Стал/, /R-AcademicEnd-0\d\d/регулярное выражение: ^ начало, $ конец, \d цифра

Текст ищется только в заметках и холстах; file: и path: находят любые файлы. Встроить результаты в заметку — блок ```query. Как Obsidian понял запрос — Explain search term в настройках поиска.

Три правила. Пути — через /, не \. Звёздочка * не шаблон: path: и file: уже ищут часть строки. Оператор действует на одно слово: path:a OR b ищет b в тексте; нужно path:a OR path:b или группа path:(a OR b) (Explain search term: «Match file path → Match any of»).
